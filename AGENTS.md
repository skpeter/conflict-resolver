## Learned User Preferences

- Score a rematch by how recently that pair played and how early the set sits in the bracket. The organizer view is a heat map colored continuously gray to red to orange by a 0–100% score (internal heat stays 0–1); avoid a clear-to-warm ramp that muddies mid heat. Heat percentage labels in suggestion previews use that same palette. Tapping a set opens the last meeting.
- A round-2 set where one player is projected because of a bye (a bye prerequisite, or a bye set start.gg omitted) heats like round 1, because players do not see the bye. The set after that stays round 3. Do not score that match as round 2, and do not switch the shorter real chain to Math.max.
- Score history as of the loaded event's start for both past and upcoming events, and ignore later meetings and that event's own sets. Completed events are how the algorithm gets validated.
- Later rounds must include projected matchups from the initial seeding for both past and upcoming events. start.gg does not return those projections, and a later slot that is still empty still needs heat so round 2 and beyond can be seeded.
- Show seed suggestions only for the selected set, and keep them small enough that they do not drastically change the original seeding. Push seeds only while no set in the phase has started; after that, edits are manual, the bracket is never reset, and suggestions still slide the initial seeding while the heat map follows reported results.
- Name the player a suggestion swaps with, and keep the seed number beside the tag. State the hottest heat left on the bracket once on the card. Omit a this-set cool-to-0% line on the move itself. The click preview lists only matchups that carry heat; hide byes and 0%→0% swaps. Put placement-tie wording (tied for Nth) in italic.
- Keep a suggestion when it cools the selected set and every set it heats stays below that set's current heat. Also list same-tier swaps even when they heat another set. A swap that drops a player into a worse placement tier is still allowed; show that drop, and use the placement bands for this bracket format.
- Do not list bye sets. The player who receives the bye advances, and the next real match is what shows. Leave Grand Final Reset off the list too.
- Last played set details include the tournament name beside the event name, a rounded relative age vs the loaded event start with a before-this-event suffix (days/weeks/months), and Winner as the player tag only. Ignore DQ-reported sets when choosing the most recent meeting. Set links go directly to the set (`/tournament/{slug}/event/{event}/set/{id}`) without showing the set id and must not add a second `tournament/` segment.
- Keep start.gg tokens and OAuth client secrets out of chat and out of git. The published UI signs in with start.gg OAuth; do not add a paste-token field. For a live API run from this agent, the event link is enough: read the gitignored `startgg.token.local` file in the repo root and do not print it. Do not ask for the token. A token set only in the user's own PowerShell window is not visible to the agent shell.
- After a bracket loads, show tournament name, event name, and whether seeding edits are still allowed on separate lines; put entrant count in the phase card title next to the phase name.
- Publish the static app with GitHub Actions to GitHub Pages. That workflow runs `npm test` and the production build before deploy, and `npm test` only runs the files named in `package.json`. Production OAuth needs repository variables `VITE_STARTGG_CLIENT_ID` and `VITE_OAUTH_WORKER_URL`. The Cloudflare Worker in `worker/` holds `STARTGG_CLIENT_SECRET`.

## Learned Workspace Facts

- Conflict Resolver is the public Vite/React app at https://github.com/skpeter/conflict-resolver, published from `main` to https://skpeter.github.io/conflict-resolver/. Version 1 is a one-page singles single-elim or double-elim audit with no account and no stored bracket; each visit refetches start.gg. The shell is dark. Brand with the Team Polygon mark in the title and favicon. Support uses the official Ko-fi button to https://ko-fi.com/teampolygonbr.
- OAuth access and refresh tokens stay in tab memory (`sessionStorage`) and are sent only to `https://api.start.gg/gql/alpha` (access) and the OAuth Worker (refresh). Only the two Advanced multipliers are stored in `localStorage`. The Worker exchanges the authorization code; it does not proxy GraphQL. start.gg OAuth redirect URIs are production-only, so local Vite should point `VITE_OAUTH_WORKER_URL` at the deployed Worker rather than a stopped wrangler localhost.
- start.gg `completedAt` and `event.startAt` are unix seconds. The heat window is 60 days in milliseconds. Convert seconds (values under 1e12) before comparing, or every meeting looks older than the window and shows no heat.
- The start.gg client stays at or under 80 requests per 60 seconds. Do not raise that cap until start.gg's real limit is known. History asks for up to 100 sets per pair, eight pairs per request, and splits a batch in half when start.gg rejects a response for more than 1000 objects. A page that is still too large is retried at half the page size; one pair that cannot shrink enough stays failed and does not hide the rest of the batch. A one-completed-set page is the smaller shape to try next, because unfinished sets matter only when a result was never reported, but do not switch until a live run returns the same receipts in fewer calls.
- start.gg omits bye matches and seats those players in the next round. Projection has to follow the prerequisite graph, or later pairs never appear. A bye has fewer than two players, so it is not sent as a history query.
- Seed writeback uses `updatePhaseSeeding` and only while the phase is unplayed. Once the bracket has started, start.gg locks seeding, and resetting the bracket clears reported scores.
